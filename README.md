## 还原

1. `git clone <repo>` 到任意目录
2. 用 ModMind 打开该目录（整合包 / NeoForge 1.21.1）
3. 按 `mods.lock.json` 的记录补齐 `mods/`（第三方 jar 不入库）
4. 启动客户端。`mods/` 只有 jar、`.modmind/` 为空都是正常状态

## 运行要求（实测）

- **堆内存 ≥ 4 GB**。本包已验证配置为 6144 MB；**1024 MB 会在模组加载阶段 `java.lang.OutOfMemoryError: Java heap space` 直接崩溃**（2026-11-04 实测）。
- JVM/加载器：NeoForge 21.1.265，Java 21（64-bit）。
- 已启用模组 48 个 jar（另有 2 个 `.disabled`）；杂项列表显示的 mods 数会更多，属正常（含 jar-in-jar 嵌套库）。
- 光影四件套版本是锁死的，改必崩，版本表见 [文件/教程/教程-钢铁潮汐是怎么做出来的.md](文件/教程/教程-钢铁潮汐是怎么做出来的.md) §5。

## 已知环境问题

ModMind 的托管清单 `modmind.pack.json` 还停在 2026-11-04 的 13 条记录，而 `mods/` 实际是 48 个 jar，所以托管构建能编出 jar 但**同步和启动会被审计拦住**（报缺 `sodium-0.8.13`、`tacz-1.1.8`）。实机验证目前走 PCL 实例；要让 ModMind 托管实例恢复可用，得先把托管清单与真实 `mods/` 对齐。

## 提交约定

- 第三方 jar 永不入库；版本以 `modmind.pack.json` 为准
