## 二、当前卡点：弹药组装（接手第一件事）

### 已经确认能用的部分

KubeJS 里直接调 TaCZ 的 builder 能造出带弹种的弹药：

```js
let one = Java.loadClass('com.tacz.guns.api.item.builder.AmmoItemBuilder')
    .create()
    .setId(Java.loadClass('net.minecraft.resources.ResourceLocation').parse('tacz:762x39'))
    .setCount(1)
    .build()
```

日志确认产物组件里有 `minecraft:custom_data=>{AmmoId:"tacz:762x39"}` —— 弹种正确。

### 卡在哪

`setCount(5)` 会失败：

```
Item stack with stack size of 5 was larger than maximum: 1
```

TaCZ 弹药 `max_stack_size = 1`，配方 result 必须遵守堆叠上限。TaCZ 自己的枪械工作台能出 35 发，是因为它用自定义 result 格式 `{type:"ammo", id, count:35}`，不走标准 ItemStack。

### 正在试的方案（v4，**没跑过**）

`mod_l61phe/.modmind/minecraft/kubejs/server_scripts/irontide_ammo_probe2.js`：

```js
let one = AmmoItemBuilder...setCount(1).build()
event.shapeless([one, one.copy(), one.copy(), one.copy()], ['minecraft:iron_ingot'])
```

思路是每个堆只放 1 发，一次给多个堆。

**启动一次看两行**：
- `[irontide] 单发 = 1 tacz:ammo, count = 1, max = 1`
- `Added N recipes, ... with 0 failed recipes`

### 如果 v4 失败，备选顺序

1. `event.recipes.create.mixing` 的 result 传数组（Create 的配方编码器对多产物更宽松）
2. `event.custom({...})` 手写 JSON，result 用 TaCZ 的自定义格式 —— 但只有 TaCZ 的 `gun_smith_table_crafting` 认那个格式，需要注册到 TaCZ 的 recipe type 上
3. 放弃"一次多产"，配方固定出 1 发，靠"成本低"平衡（1 弹壳 → 1 发已经能自动化）

### 成本参考（配方定下来时按这个配）

| | 产出 |
|---|---|
| 1 铜锭 | → 1 铜板 → **2 弹壳**（Create 压片 + 动量锯） |
| 1 火药 + 1 木炭 | → **2 发射药**（搅拌机，不需加热） |
| TaCZ 原版 | 15 铜锭 + 3 火药 → 35 发（1 铜锭 ≈ 2.33 发） |

拟：`1 弹壳 + 1 发射药 + 2 铁粒 → 4 发`（1 铜锭 ≈ 8 发，比原版宽松三倍）。**这个数还没跟用户确认。**

## 三、必须知道的约定

### 构建

```bash
cd E:/ioncreating/mod_l61phe/modules/irontide
GRADLE_USER_HOME="C:/Users/25571/AppData/Roaming/modmind/gradle-runtime/cache" ./gradlew build --offline
```

- **必须用这个 `GRADLE_USER_HOME`**。默认的 `E:\ailian\工具\gradle-home` 里没有 `neoform-runtime`，而 `maven.neoforged.net` 本机不可达（curl 20s 超时）→ 联网和离线都会失败在 `:createMinecraftArtifacts`。
- 查 API 用 `modules/irontide/build/moddev/artifacts/neoforge-21.1.265-merged.jar`。
- 当前 jar：`144078 B`，sha256 `2b86e699bc64812552d86848709e017673886dbf045dd1997afcbe1d36956108`。

### 改完必须同步两处

```bash
cp build/libs/irontide-0.1.0.jar ../../mods/modmind-local-irontide.jar
cp build/libs/irontide-0.1.0.jar ../../.modmind/minecraft/mods/modmind-local-irontide.jar
```

- `mods/` = 发版用；`.modmind/minecraft/mods/` = 本地测试实例用。只改一处会出现「本地好好的，发出去没了」。

### 配置也要同步两处

`modules/irontide/src/main/resources/data/irontide/config_defaults/*.json`（模组内置默认）和 `overrides/config/irontide/*.json`（发给玩家）。改一处必须改另一处。

### 数值全部走 JSON

`config/irontide/core.json`（核心/燃料/模块/应力）、`raids.json`（怪潮/安全区）、`multiblocks/core_base_3.json`（结构）。调数值不用重新编译，改 JSON + `/reload` 就行。

### 验证产物，不验证退出码

Gradle 说 SUCCESSFUL 不等于 jar 里有东西。每次都 `unzip -l` 查一遍。踩过：漏 `models/item/xxx.json` → 物品显示粉紫格子。

## 四、九个坑（省时间用，详细版见教程）

完整版在 `docs/教程-钢铁潮汐是怎么做出来的.md` §5，这里只列触发条件：

| 现象 | 原因 | 解法 |
|---|---|---|
| `找不到符号: fuelValues()` | 那是 1.21.2+ 的 API | 用 `ItemStack#getBurnTime(RecipeType.SMELTING)` |
| `saveAllItems` 签名对不上 | 1.21.1 没有 `(tag, container)` 重载 | 改用 `SimpleContainer#createTag/fromTag` |
| KubeJS `Unknown event 'genericLootTables'` | 1.21 已删，挪到 LootJS | 用 NeoForge GLM 纯 JSON（已实现） |
| KubeJS `redeclaration of var X` | 脚本在同一作用域执行两遍 | 不声明任何顶层变量，需要就内联 |
| 装 mixin 模组启动崩 | `defaultRequire:1`，一个注入点找不到就全崩 | 装前 `javap` 核对目标方法签名 |
| 光影崩 / Veil 报 sodium 版本 | Sodium/Iris/irisveil/SodiumExtra 四者版本死锁 | 锁死组合见下 |
| 模组启动报 `Empty pre-release` | `mods.toml` 版本号 `3.1-1.21.1+` 的 `+` 后面是空的 | 拆 jar 改一行去掉 `+` |
| 手臂渲染错乱（不崩） | punchy 与 firstperson 抢同一批 mixin | 只留一个，另一个改名 `.disabled` |
| 持剑时枪飘在第一人称 | TaCZ 把非主手枪当挂件渲染 | `tacz-client.toml` 的 `DisableThirdPersonOffhandAndHotbarGunRender = true` |

**光影锁死的四行（改了必崩，别动）**：

| 模组 | 版本 |
|---|---|
| Sodium | `0.8.12+mc1.21.1`（**不能 0.8.13**） |
| Iris | `1.8.14-beta.1+mc1.21.1` |
| irisveil | `0.4.0` |
| Sodium Extra | `0.9.3`（**不能 0.9.5**，那边写死依赖 0.8.13） |
