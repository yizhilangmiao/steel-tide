# irontide 配置契约

> 这两个文件由 IronTide 服务端在启动时**只读一次**并做范围校验；改数值不用重新编译，重启客户端生效。

| 文件 | 作用 | 谁读 |
| --- | --- | --- |
| `core.json` | 全局参数：血量、燃料、应力、机壳分级、档位上限、模块数值 | IronTide 服务端，载入时校验 |
| `raids.json` | 怪潮：周期、波次表、刷怪、安全区、攻核、怪物来源 | IronTide 怪潮调度器，载入时校验 |
| `multiblocks/core_base_3.json` | T1（3×3×3）内置结构 | IronTide 结构校验器 |

## 燃料容量与模块

| 情况 | 容量 | 燃烧效率 | 每秒消耗 |
| --- | --- | --- | --- |
| 不装燃料模块（应急） | `fuel.noFuelModuleCapacity` = 12000 | `fuel.noFuelModuleEfficiency` = 1.5 | `burnPerSecond / 1.5` ≈ 3.3 |
| 燃料模块 I | `modules.fuel[0].capacity` = 60000 | 1.00 | 5 |
| 燃料模块 II | `modules.fuel[1].capacity` = 120000 | 0.80 | 6.25 |
| 燃料模块 III | `modules.fuel[2].capacity` = 240000 | 0.60 | 8.3 |

- **面板/聊天里的上限、百分比、低燃料阈值全部按「当前装的模块容量」算**（`AndesiteCoreBlockEntity#getFuelCapacity()`）。
- `fuel.capacity`（12000）是旧版遗留字段，仅为兼容老配置保留，**不再参与计算**。
- 效率越低烧得越快：容量换效率是燃料模块的核心取舍；模块数值在 `core.json → modules.fuel[]` 里调。
## 机壳材质与档位门槛

`core.json → casing` 现在是**数组**（顺序即默认优先级），每种材质一项：

| 材质 | 世界方块 `id` | 成型壳 `formed` | 生命倍率 | 护甲 | 燃料效率 | `minTier` |
| --- | --- | --- | --- | --- | --- | --- |
| 安山 | `create:andesite_casing` | `irontide:shell[type=andesite]` | 1.00 | 0.00 | 1.00 | 1 |
| 黄铜 | `create:brass_casing` | `irontide:shell[type=brass]` | 1.60 | 0.05 | 1.15 | 1 |
| 铜 | `create:copper_casing` | `irontide:shell[type=copper]` | 1.45 | 0.06 | 1.45 | 2 |
| 钢 | `create:industrial_iron_block` | `irontide:shell[type=steel]` | 2.20 | 0.12 | 1.00 | 3 |

- **生命倍率 / 护甲按格数加权平均**：`Σ(格数 × 该材质值) / 外壳总格数`，四种材质混搭时每种按自己的占比贡献。
- **`minTier` 是门槛**：核心档位序号（T1=1 … T4=4）低于门槛时，用这种材质搭的结构判为**不完整**，该格计入缺失并触发还原，避免 T1 直接铺钢壳。
- 外壳格可以放任意一种材质：成型时按**当前方块**决定换成哪种壳，校验时壳类型不必与结构图一致。
- 老配置仍可用：`casing` 写成对象 `{"andesite":{...},"brass":{...}}` 会按字段顺序读成数组。

## 约定

1. **只读一次**：服务器启动时载入并做范围校验，非法值直接报错停止，**不允许静默回退默认值**
2. **改数值不动代码**：调平衡只改这些文件，重启生效
3. **结构格式**：`layers` 的键是相对控制器的 Y 偏移，每个字符串是一层（Z 从北到南），一个字符一列（X 从西到东）
4. **图例**：`legend` 把一个字符映射到一个方块 id；`B` 允许出现在 `#` 的位置（外壳可收安山/黄铜/铜/钢，受 `minTier` 门槛限制）
5. 标注 `_placeholder` 的字段是待实测平衡值，不是最终数值

## `raids.json` 关键字段

| 字段 | 含义 |
| --- | --- |
| `spawn.perBurst` / `spawn.intervalTicks` | 每轮刷几只 / 两轮之间隔多少 tick |
| `spawn.maxAlive` | **同时存活上限**，`0` = 不限。到顶后暂停刷怪，清掉一批再继续，避免几十只同屏掉帧 |
| `spawn.chaseRadius` | **寻路半径**。半径内交给原版 A* 寻路，半径外只做直线移动（每 3 秒补一次真寻路兜底），大幅降低怪多的寻路开销 |
| `spawn.glowWhenAliveBelow` | 剩余来袭怪**少于这个数**时给每只挂发光（默认 10；`0` = 关闭），收尾时好找漏网的 |
| `spawn.arcDegrees` | **主攻扇面张角**（度，默认 60）。每波开打先抽一个方位，整波怪都落在该方位 ±一半张角的扇面里一起压过来；`0` = 几乎排成一条线，`360` = 恢复四面八方随机 |
| `minWaveSize` | 单个**小波**规模下限（默认 32）。波次表的 `base` 低于它按它算，保证「一小波不少于 32 只」 |
| `spawn.waveGapTicks` | 小波之间的间隔（tick，默认 3600 = 3 分钟）。一大波 3 小波，小波清完后等这个时间再开下一小波 |
| `spawn.early.singleSideBigWaves` / `firstBigWaveSide` | 前 N 个大波三小波同向（默认 3）；第一个大波固定从 `west` 来 |
| `attack.damagePerSecond` / `attack.dpsCap` / `attack.intervalTicks` | 每只围核怪的平均 DPS / 全程平均 DPS 上限（`0` = 不限）/ 全局脉冲间隔（默认 100 = 5 秒） |
| `gearMulMax` | 规模按核心档位缩放的上限（T1 → ×1.00，最高档 → ×(1 + gearMulMax)） |
| `waves[]` | 每波基础怪数（当前 32 / 38 / 44 / 50 / 56 / 62 / 68 / 74）、词缀数、词缀等级 |

## 核心网络（前哨）

`core.json → network`

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `radius` | 96 | 同维度、距离 ≤ 半径的 ACTIVE 核心与主核组成一张网络。只认已加载的核心，不扫描区块 |
| `shareDamage` | true | 多座前哨同时挨打时，伤害在前哨之间均摊（每座至少 1 点）；`false` = 各挨各的 |
| `settlementSplit` | true | 残骸按存活前哨数拆份，每份给该前哨 128 格内最近的玩家；没人接就并回全员 |
| `mainCoreInvulnerable` | **false** | 主核**有血**：主核与前哨一起承伤；设为 `true` 才回到旧的「只打前哨」模式 |

- 前哨不是新方块：任何**成型且运转中**的核心，落在主核网络半径内就自动加入网络。
- **主核有血**：归零 = 停机，由网络里还活着的核心接替锚点；全灭 = 本波提前失败、无奖励。
- **HUD**：显示血量比例最低的承伤核心（主核或前哨，看谁最吃紧）。
- **结算**：`当前网络内承伤核心总血量 ÷ 开战时的总上限`，除法公式未变；无前哨时主核自己委伤，结算按主核血量比例算。
- **保护区内前哨**：落在主核 `r≤26` 的前哨不进承伤集合、不提供加成，开战时播报「前哨位于保护区内，本波无法攻击」。
- `radius` 校验 [8, 256]，越界拒绝启动；老配置没有 `network` 段时按 96 / true / true / **true** 走（老行为）。

## 领地分区（方形）

判定用切比雪夫距离 `r(x,z)=max(|x-cx|,|z-cz|)`，**y 不参与**（`safeZone.halfHeight` 仅作可选兜底）。

| 分区 | 半径 | 规则 | 视觉 |
| --- | --- | --- | --- |
| 建造保护区 | `r≤26` | 方块不可拆 | 绿 `#3CFF6E`，画在 `r=25` |
| 空气墙 | `r=26`（夹在 `26.35`） | 实体级，无方块；只拦来袭怪 | — |
| 防御区 | `27–40` | 可拆 | 黄 `#FFD23C`，画在 `r=27` 与 `r=40` |
| 缓冲带 | `41–44` | 空置 | — |
| 刷怪环 | `45–60` | 跳出点 | — |

- **空气墙**只对 `raiders` + `defense.denyEntities`（默认空）生效，每 2 tick 把水平位置夹回 `26.35`；不拦玩家、被动生物、投射物，飞行怪同样夹。
- **方形角落效应**：`r=26` 的角点到中心欧氏距离 ≈ 36.8，`45–60` 环角点 ≈ 63.6–84.9，都大于 `spawn.chaseRadius=48`。角落方向的怪会先用直线移动，靠近后才交给 A* 寻路，这是有意为之（避免几十只怪同时寻路）。
- 领地跟随主核 `ACTIVE` 生效；停机/摧毁后领地粒子关闭；主核失守后领地跟随接替前哨。
- `safeZone.lightUp` 默认 `false`：铺光可选，默认不铺。

## 攻核脉冲（`raids.json → attack`）

核心受击是**全局同步 5 秒脉冲**，不是每只怪各自计时：

- 调度器只有一个时钟：`attack.intervalTicks`（默认 100）递减到 0 时统一结算一次。
- 接触集合 = 近身（`attack.range`）∪ 贴墙（空气墙 `26.35`），按 UUID 去重；同一只怪只算一次。
- 每只怪单次伤害 = `damagePerSecond × intervalTicks / 20`（默认 `2 × 5 = 10`）。
- 全局单次上限 = `dpsCap × intervalTicks / 20`（默认 `16 × 5 = 80`）。
- **平均 DPS 不变**：压力看 `damagePerSecond` 与 `dpsCap`，`intervalTicks` 只影响节奏。
- 播报跟随脉冲、90 秒冷却；脉冲时核心有粒子与音效反馈。

### 5000 血换算表（每次脉冲每只 10 点，全局封顶 80）

| 贴核怪数 | 每 5 秒总伤害 | 打空 5000 血约需 |
| --- | --- | --- |
| 3 只 | 30 | 约 14 分钟 |
| 5 只 | 50 | 约 8 分钟 |
| ≥8 只 | 80（封顶） | 约 5 分钟 |

## 拆墙（`raids.json → break`）

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | 缺省段时 false；示例配置为 true | 总开关 |
| `intervalTicks` | 20 | 每只怪隔多久尝试敲一格（≥5） |
| `maxPerTick` | 4 | 每次调用最多敲/拆几格（全局每 tick 上限 ≤4） |
| `range` | 40 | 离目标核心多近才开始拆（[4, 64]） |
| `maxProgress` | 120 | 单块上限：按硬度算出的需求次数不超过它，保证黑曜石最终可破 |

- 按方块坐标判定：`r≤26` 不可拆，`r≥27` 任何方块都可拆（不再有白名单）。
- 永久保护名单：`bedrock / barrier / 三种命令方块 / structure_block / irontide:andesite_core / irontide:shell`。
- **按硬度累积**：需求次数 = `clamp(ceil(硬度 × 4), 4, maxProgress)`；木板 8 次、石头 6 次、铁块 20 次、黑曜石封顶 120 次。
- 无掉落；命中播放方块音效 + 碎屑粒子，破坏时播放破坏音效。
- 进度表每波清空、最多记 256 格——不会因为玩家乱搭把内存/主线程拖死。

## 填沟（`raids.json → fill`）

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | 缺省段时 false；示例配置为 true | 总开关 |
| `block` | `minecraft:cobblestone` | 填充方块 |
| `perRaiderPerWave` | 8 | 每只怪每波最多填几块 |
| `globalPerWave` | 128 | 全局每波最多填几块 |
| `perTick` | 1 | 每次调用最多填几块 |
| `maxDepth` / `maxWidth` | 4 / 3 | 只填深 2–4、宽 ≤3 的沟 |

- 只对 `r≥27` 生效；从沟底往上填，25/26 内不填。

## 前哨定位（`raids.json → outpost`）

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `minRadius` / `maxRadius` | 44 / 60 | 前哨相对主核的建议距离 |
| `sameSideDegrees` | 45 | 前哨与本次主攻方位的角差 ≤ 它时，刷怪锚点改到前哨 8 格外 |
| `spawnRadius` | 8 | 同向前哨的刷怪环半径 |

- 优先级：同向且前哨可打 → 前哨；不同向 → 主核；16 格内有玩家 → 玩家。

## 旧存档与血量上调

- `core.json → health.base` 从 500 提到 5000，外壳倍率不变（安山 5000 → 钢壳 11000）。
- `healthMax / structureHealthMax` 是**存在方块实体 NBT 里的旧值**，只在结构成型/校验时重算。
- 旧存档里已经成型的主核，下次结构校验（区块加载、放置方块、每 100 tick 巡检）会**按旧比例继承新上限**：血量比例不变，上限跟随配置。日志会打一条 `health cap updated`。
- 若想回到满血，请拆掉核心重新成型（或用修复工具）；旧存档不会再停在 500/500。
- `minRatioOnUpgrade=0.0` / `carryRatioOnUpgrade=true` 的升级收益会跟着 5000 基数放大，配装时请按新基数计算。

## 性能日志（MSPT）

怪潮期间每 100 tick（5 秒）打一行：

```
[IronTide] raid perf mspt=12.4 peak=18.9 raiders=14
```

- `mspt` = 本窗口平均每 tick 毫秒（自算，不含渲染/GC）；`peak` = 本波最高窗口平均；`raiders` = 本波峰值同屏怪数。
- ≥ 50ms（低于 20 TPS）时改打 `warn`，句尾带「低于 20 TPS」。
- 波次结束时结算日志追加 `peakMspt=`，用于比对「怪更多后掉不掉 TPS」。
