## 1. 用例

| # | 操作 | 预期 | 失败判据 |
|---|---|---|---|
| **S1** 四态·未成型 | 新放一个核心，不搭外壳 | 右键核心：面板第一行显示 `状态 未成型`，下面一行 `缺口 N 格` | 显示「运转中」/ 面板空白 |
| **S2** 四态·运转中 | 搭满结构、投入燃料 | 面板显示 `状态 运转中`，燃料条正常 | 显示未成型 |
| **S3** 四态·燃料不足 | 让燃料掉到 15% 以下 | 面板显示 `状态 运转中 · 燃料不足` | 无变化 / 报错 |
| **S4** 四态·停机 | 燃料清零（面板有「清空燃料」按钮） | 面板显示 `状态 停机（无燃料）`，动力输出停 | 仍显示运转中 / 客户端崩 |
| **S5** 四态·已摧毁 | 把核心血量打到 0（用命令或让怪围） | 面板显示 `状态 已摧毁（需要维修）` | 崩服 / 状态错乱 |
| **S6** 聊天状态行 | 右键核心（非潜行，空手） | 聊天里出现 `<T1> · <上面那个状态>`，例如 `[钢铁潮汐] T1 · 运转中` | 仍显示「已激活」旧文案 |
| **S7** 同时存活上限 | 临时把 `raids.json` 的 `spawn.maxAlive` 改成 `4`，重启，`/time set night` 触发怪潮 | 同屏最多 4 只来袭怪；杀掉一只马上补一只，总数仍按波次刷完 | 一次冒出十几只 / 补不上 |
| **S8** 远怪不寻路 | 同上，`chaseRadius` 默认 48 | 远处怪直线朝核心走（可能卡树），进 48 格后恢复绕障寻路；整波期间 TPS 不明显掉 | 远怪原地不动 / 卡在 48 格外绕圈 |
| **S9** 档位参与规模 | 把 `core.json` 的 `tiers` 保持默认，先用命令看日志 | 日志 `怪潮第 N 波开始` 的目标数与「基础 × 人数 × 档位系数」一致（T1 = ×1.00） | 目标数明显偏大且与档位无关 |
| **S10** 老配置兼容 | 把 `raids.json` 里 `maxAlive` 和 `chaseRadius` 两行**删掉**，重启 | 正常启动，行为等同 `maxAlive=0`（不限）、`chaseRadius=48` | 启动报配置错误 |

## 2. 怎么判定

```powershell
Select-String -Path "D:\mc\versions\钢铁潮汐-开发\logs\latest.log" -Pattern "IronTide|怪潮" | Select-Object -Last 30
```

正常：

```
[IronTide] raids.json loaded from ... (waves=8, cycleDays=10)
[IronTide] ... activated: layout=rot90 health=... shell=23 brass=...
[钢铁潮汐] 怪潮第 1 波开始！目标：安山核心（14 个来袭）。
```

异常：

- `spawn.maxAlive must be >= 0` / `spawn.chaseRadius must be within [8, 128]` → 配置写错了（这是**故意**的：非法值直接拒绝启动，不静默回退）。
- 怪潮期间 TPS 掉到 15 以下且 `maxAlive` 已经设成 ≤8 → 把 `chaseRadius` 调到 32 再试，并把日志发我。

## 3. 已知限制（不是 bug）

- 远怪只做直线移动，**会卡树/卡墙**，3 秒一次的兜底寻路才纠正；这是拿一点路径愚蠢换 TPS。
- `maxAlive` 只限制**同时存活**，不减少整波总数；守完仍然要清掉全部目标。
- 面板四态里「燃料不足」不是独立状态，算在「运转中」的附加说明里。
