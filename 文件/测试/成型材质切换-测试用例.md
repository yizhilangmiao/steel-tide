## 1. 快速搭建（复制粘贴到聊天框逐条执行）

站在要放核心的位置，依次执行。`~` 都是相对你自己：

```
tp @s 0 200 0
fill ~-1 ~-1 ~ ~1 ~-1 ~2 create:andesite_casing
fill ~-1 ~ ~ ~1 ~ ~2 create:andesite_casing
fill ~-1 ~ ~1 ~1 ~ ~1 create:gearbox
fill ~-1 ~1 ~ ~1 ~1 ~2 create:andesite_casing
setblock ~ ~ ~ irontide:andesite_core
```

结构长这样（控制器 `C` 在最外一排的中间，三个 `G` 是齿轮箱）：

```
层 y-1       层 y              层 y+1
###          #C#               ###
###          GGG               ###
###          ###               ###
```

> 一共 27 格：23 格机壳（`#`）、1 格控制器、3 格齿轮箱。只有机壳会被换成 `irontide:shell`。
> `fill` / `setblock` 不算玩家放置事件，所以以前要右键核心才会判定；现在有**每秒自检**，最多 1 秒后自动成型。

搭完退后 4 格回头看：`tp @s ~ ~ ~-4 0 0`

## 2. 用例

| # | 操作 | 预期 | 失败判据 |
|---|---|---|---|
| **T1** 未成型不换 | 只执行 `setblock ~ ~ ~ irontide:andesite_core`，不搭外壳 | 结构不完整，机壳保持原样（没有 `irontide:shell`） | 出现壳 = 不该预先换壳 |
| **T2** 补满即换 | 执行第 1 节全部命令 | ≤1 秒内 23 格机壳全变 `irontide:shell`（灰、带铆钉边框），齿轮箱和核心不变 | 只有部分格变了 / 完全没变 |
| **T3** 不抖动 | 成型后站原地看 2~3 分钟 | 核心一直 ACTIVE，血量不反复重置，日志不刷屏 | 每秒 `activated`/`incomplete` 交替刷新 = 校验抖动 |
| **T4** 混黄铜 | 成型前把几格 `#` 改成 `create:brass_casing`，再补满 | 黄铜那几格变成金黄色的 `shell[type=brass]`，其余仍是灰壳 | 全变一个颜色 / 血量倍率算错 |
| **T5** 拆一格还原 | 手动挖掉任意一格壳 | 其余壳全部变回 `create:andesite_casing`；被挖那格掉一个安山机壳物品 | 壳永久卡住 / 挖了拿不到东西 / 掉双份 |
| **T6** 重启保持 | 成型后退出到标题再进 | 壳仍然是壳；再挖一格 → 照样整体还原 | 重启后壳变回机壳 / 拆了不还原 |
| **T7** 拆核心 | 直接破掉核心方块 | 所有壳同时还原成原机壳，不留下无主孤壳 | 地上留一片灰壳且挖不掉/挖了没反应 |
| **T8** 总开关 | `core.json` 里 `materialSwap.enabled: false`，重启 | 搭满后**完全不换壳**，其余逻辑（激活、血量、供能）照常 | 关掉还换壳 = 开关没接上 |
| **T9** 外力破坏 | 成型后 `setblock <某格壳> minecraft:stone` | ≤1 秒内整体还原，不崩服、不复制方块 | 客户端崩溃 / 方块翻倍 |
| **T10** 压力（可延后） | T4/T3 大结构（edge=9，729 格）搭满 | 换壳分批推进（≤64 格/秒级），不出现明显卡顿 | 单帧卡死数秒 |
| **T11** TNT 炸壳 | 成型后用 TNT（或 `summon tnt`）炸掉任意一格壳 | 5 秒内（TNT 引信+自检）**该核心全部 23 格壳都还原**成机壳，包括核心方块左右两侧那几格 | 只还原了一部分（典型：控制器旁边一列仍是灰壳） |

### 建议顺序

先 T1 → T2（核心功能一次看完）→ T5（还原）→ T11（TNT 还原）→ T6（存档）→ T3（抖动）→ 其余按兴趣。

### 回归点（本轮修复）

- **rot90 成型后挖/炸非 rot0 朝向的壳**：结构不对称，核心贴边，成型朝向可能不是 rot0。以前还原按 rot0 字符表判断，会漏掉一整列（实测每台漏 8 格）。现在按「壳归属的控制器」判定，任何朝向成型都能完整还原。
- **成型后外壳被破坏、核心仍是 ACTIVE** 的情况：自检现在对 `ACTIVE` 状态也生效，外壳缺失会立刻整体还原，不会留下残余壳。

## 3. 怎么看日志判定

实例目录 `logs/latest.log`（PCL 的「打开游戏目录」可直接进）。命令行：

```powershell
Select-String -Path "D:\mc\versions\钢铁潮汐-开发\logs\latest.log" -Pattern "IronTide" | Select-Object -Last 20
```

正常会看到（各一条，不应刷屏）：

```
[IronTide] core_base_3 at (1, 200, 1) activated: layout=rot90 health=539/... shell=23 brass=3
[IronTide] formed 23 cells at (1, 200, 1)
[IronTide] incomplete: layout=rot90 missing 9/27 [...]
[IronTide] unformed 23 cells at (1, 200, 1)      ← 拆/炸之后
```

**关键判据：`unformed N cells` 的 N 必须等于 `formed N cells` 的 N**（都是 23）。如果 `unformed` 明显小于 `formed`，就是漏格。

异常信号：

- `incomplete: ... missing N/27` 每秒重复 → 校验抖动（把 `materialSwap.enabled` 先关掉，把日志发我）。
- `StackOverflowError` / `Exception` 堆栈 → 立刻关开关并抓 `latest.log` + `crash-reports`。

## 4. 已知限制（不是 bug）

- **只有安山款有物品**：创造栏里的「结构外壳」固定是 `type=andesite`。黄铜/钢/铜款目前只能通过成型或 `/setblock irontide:shell[type=brass]` 出现。
- **壳不能单独存在**：手放或用命令放的壳，1 秒内会自己消失（没有控制器归属）。这是设计行为。
- **只换机壳**：齿轮箱、核心、其它方块不参与换壳。
- **`/setblock` 破坏了结构会立刻整体还原**（T9 就是这个行为）。
- **TNT 炸掉的格保持空气**，不会被补回成机壳——还原只处理「还活着的壳」。
