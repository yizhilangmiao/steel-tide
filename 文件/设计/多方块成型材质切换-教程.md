> 读完能做到：`core_base_3` 搭满后，外壳从 Create 的 casing 变成 `irontide:shell` 的精致金属板；拆掉任意一格，全体还原成原方块；服务器重启不丢状态。
> 全程**不需要建模**、不需要改渲染代码、不需要 Blender。
> 配套方案见 [多方块成型材质切换-方案.md](多方块成型材质切换-方案.md)。

### 1.2 方块实体：壳自己记住原始状态

新文件 `src/main/java/dev/modmind/irontide/block/ShellBlockEntity.java`：

```java
package dev.modmind.irontide.block;

import net.minecraft.core.BlockPos;
import net.minecraft.core.HolderLookup;
import net.minecraft.core.registries.Registries;
import net.minecraft.nbt.CompoundTag;
import net.minecraft.nbt.NbtUtils;
import net.minecraft.world.level.block.Blocks;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;

public class ShellBlockEntity extends BlockEntity {
    private BlockPos controllerPos = BlockPos.ZERO;
    private BlockState originalState = Blocks.AIR.defaultBlockState();

    public ShellBlockEntity(BlockPos pos, BlockState state) {
        super(ModMindEntry.SHELL_BE.get(), pos, state);
    }

    public void bind(BlockPos controller, BlockState original) {
        this.controllerPos = controller;
        this.originalState = original;
        setChanged();
    }

    public BlockPos controllerPos() {
        return controllerPos;
    }

    public BlockState originalState() {
        return originalState;
    }

    @Override
    protected void saveAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.saveAdditional(tag, registries);
        tag.put("controller", NbtUtils.writeBlockPos(controllerPos));
        tag.put("original", NbtUtils.writeBlockState(originalState));
    }

    @Override
    protected void loadAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.loadAdditional(tag, registries);
        controllerPos = NbtUtils.readBlockPos(tag, "controller").orElse(BlockPos.ZERO);
        originalState = NbtUtils.readBlockState(
                registries.lookupOrThrow(Registries.BLOCK), tag.getCompound("original"));
    }

    /**
     * 自愈：控制器没了、或者记录的原始状态是空气，就自己消失。
     * 这一步保证「壳永远不会脱离控制器独立存在」，避免存档里卡一堆无用方块。
     */
    @Override
    public void onLoad() {
        super.onLoad();
        if (level == null || level.isClientSide()) {
            return;
        }
        if (originalState.isAir()) {
            level.removeBlock(worldPosition, false);
            return;
        }
        if (!(level.getBlockEntity(controllerPos) instanceof AndesiteCoreBlockEntity)) {
            BlockState restore = originalState;
            level.removeBlock(worldPosition, false);
            level.setBlock(worldPosition, restore, 3);
        }
    }
}
```

> 这里 `saveAdditional/loadAdditional` 能正常重写，因为父类是 `BlockEntity`。
> 控制器的 `AndesiteCoreBlockEntity` 父类是 `SmartBlockEntity`，那两个方法被 `final` 了——两者不一样，别照着控制器抄。

### 1.3 方块本体

新文件 `src/main/java/dev/modmind/irontide/block/ShellBlock.java`：

```java
package dev.modmind.irontide.block;

import com.mojang.serialization.MapCodec;
import net.minecraft.core.BlockPos;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.BaseEntityBlock;
import net.minecraft.world.level.block.RenderShape;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;
import net.minecraft.world.level.block.state.StateDefinition;
import net.minecraft.world.level.block.state.properties.EnumProperty;
import org.jetbrains.annotations.Nullable;

public class ShellBlock extends BaseEntityBlock {
    public static final EnumProperty<ShellType> TYPE = EnumProperty.create("type", ShellType.class);

    public ShellBlock(Properties properties) {
        super(properties);
        registerDefaultState(defaultBlockState().setValue(TYPE, ShellType.ANDESITE));
    }

    @Override
    protected MapCodec<? extends BaseEntityBlock> codec() {
        return simpleCodec(ShellBlock::new);
    }

    @Override
    protected void createBlockStateDefinition(StateDefinition.Builder<net.minecraft.world.level.block.Block, BlockState> builder) {
        builder.add(TYPE);
    }

    @Override
    protected RenderShape getRenderShape(BlockState state) {
        return RenderShape.MODEL;   // 普通方块模型，没有任何自定义渲染
    }

    @Override
    public @Nullable BlockEntity newBlockEntity(BlockPos pos, BlockState state) {
        return new ShellBlockEntity(pos, state);
    }

    /**
     * 拆壳：掉原方块（不是掉壳），然后由 BreakEvent 触发的 revalidateAround 让控制器收拾剩下的格子。
     */
    @Override
    protected void onRemove(BlockState state, Level level, BlockPos pos, BlockState newState, boolean movedByPiston) {
        if (!level.isClientSide() && !state.is(newState.getBlock())) {
            if (level.getBlockEntity(pos) instanceof ShellBlockEntity be) {
                BlockState original = be.originalState();
                if (!original.isAir() && original.getBlock().asItem() != net.minecraft.world.item.Items.AIR) {
                    Block.popResource(level, pos, new ItemStack(original.getBlock().asItem()));
                }
            }
        }
        super.onRemove(state, level, pos, newState, movedByPiston);
    }
}
```

### 3.2 `CoreConfig` 解析

`CoreConfig.parseCasing`（约 213 行）改成：

```java
private static CasingSpec parseCasing(JsonObject casing, String path) {
    String idText = JsonSupport.string(casing, "id", path + ".id");
    ResourceLocation id = ResourceLocation.tryParse(idText);
    if (id == null) {
        throw JsonSupport.invalid(path + ".id", "not a resource location: " + idText);
    }
    BlockState formed = casing.has("formed")
            ? parseFormedState(casing.get("formed").getAsString(), path + ".formed")
            : null;
    double armor = JsonSupport.number(casing, "armor", path + ".armor");
    double healthMul = JsonSupport.number(casing, "healthMul", path + ".healthMul");
    double fuelEfficiency = JsonSupport.number(casing, "fuelEfficiency", path + ".fuelEfficiency");
    return new CasingSpec(id, formed, armor, healthMul, fuelEfficiency);
}

/** 解析 "irontide:shell[type=brass]" 这种带属性的方块 id。 */
private static BlockState parseFormedState(String raw, String where) {
    String text = raw.trim();
    int bracket = text.indexOf('[');
    String idPart = bracket < 0 ? text : text.substring(0, bracket);
    ResourceLocation rl = ResourceLocation.tryParse(idPart);
    if (rl == null || !BuiltInRegistries.BLOCK.containsKey(rl)) {
        throw JsonSupport.invalid(where, "unknown block: " + idPart);
    }
    Block block = BuiltInRegistries.BLOCK.get(rl);
    BlockState state = block.defaultBlockState();
    if (bracket < 0) {
        return state;
    }
    int close = text.lastIndexOf(']');
    if (close < bracket) {
        throw JsonSupport.invalid(where, "missing ']' in: " + raw);
    }
    for (String pair : text.substring(bracket + 1, close).split(",")) {
        String[] kv = pair.split("=", 2);
        if (kv.length != 2) {
            throw JsonSupport.invalid(where, "bad property: " + pair);
        }
        state = applyProperty(state, block, kv[0].trim(), kv[1].trim(), where);
    }
    return state;
}

private static <T extends Comparable<T>> BlockState applyProperty(
        BlockState state, Block block, String name, String value, String where) {
    net.minecraft.world.level.block.state.properties.Property<?> raw =
            block.getStateDefinition().getProperty(name);
    if (raw == null) {
        throw JsonSupport.invalid(where, "unknown property: " + name);
    }
    @SuppressWarnings("unchecked")
    net.minecraft.world.level.block.state.properties.Property<T> property =
            (net.minecraft.world.level.block.state.properties.Property<T>) raw;
    return property.getValue(value)
            .map(v -> state.setValue(property, v))
            .orElseThrow(() -> JsonSupport.invalid(where,
                    "bad value '" + value + "' for property " + name));
}

/** 校验用：期望方块 -> 它的成型态。 */
public @Nullable BlockState formedFor(ResourceLocation expected) {
    if (expected.equals(andesiteCasing.id())) {
        return andesiteCasing.formed();
    }
    if (expected.equals(brassCasing.id())) {
        return brassCasing.formed();
    }
    return null;
}
```

### 5.2 成型方法

```java
private void formStructure(ServerLevel level, MultiblockDefinition definition, StructureCheckResult result) {
    if (forming || !IronTideData.config().materialSwapEnabled()) {
        return;
    }
    List<MultiblockDefinition.Cell> layout = definition.layouts().get(result.layoutIndex());
    if (layout == null) {
        return;
    }
    forming = true;
    int changed = 0;
    try {
        for (MultiblockDefinition.Cell cell : layout) {
            BlockPos pos = worldPosition.offset(cell.dx(), cell.dy(), cell.dz());
            if (pos.equals(worldPosition)) {
                continue;
            }
            if (!level.isLoaded(pos)) {
                continue;
            }
            BlockState current = level.getBlockState(pos);
            if (current.getBlock() instanceof ShellBlock) {
                continue;   // 已经是壳了，别把壳当成"原始状态"再记一遍
            }
            BlockState target = IronTideData.config().formedFor(current.getBlock());
            if (target == null) {
                continue;
            }
            level.setBlock(pos, target, Block.UPDATE_CLIENTS | Block.UPDATE_KNOWN_SHAPE);
            if (level.getBlockEntity(pos) instanceof ShellBlockEntity be) {
                be.bind(worldPosition, current);
            }
            changed++;
        }
    } finally {
        forming = false;
    }
    if (changed > 0) {
        setChanged();
        ModMindEntry.LOGGER.info("[IronTide] {} at {} formed {} cells",
                definition.id(), worldPosition, changed);
    }
}
```

## 6. 还原

```java
private void unformStructure(ServerLevel level) {
    if (forming) {
        return;
    }
    forming = true;
    int restored = 0;
    try {
        for (BlockPos pos : scanShells(level)) {
            if (!(level.getBlockEntity(pos) instanceof ShellBlockEntity be)) {
                continue;
            }
            BlockState original = be.originalState();
            if (original.isAir()) {
                level.removeBlock(pos, false);
                continue;
            }
            level.setBlock(pos, original, Block.UPDATE_CLIENTS | Block.UPDATE_KNOWN_SHAPE);
            restored++;
        }
    } finally {
        forming = false;
    }
    if (restored > 0) {
        setChanged();
        ModMindEntry.LOGGER.info("[IronTide] {} at {} restored {} cells", structureId, worldPosition, restored);
    }
}

/**
 * 找本体结构范围内的壳。只扫骨架范围，不做全区块遍历——
 * 壳不可能长在结构外面，范围外的壳交给它自己的自愈逻辑处理。
 */
private List<BlockPos> scanShells(ServerLevel level) {
    MultiblockDefinition definition = IronTideData.definitions().get(structureId);
    if (definition == null) {
        return List.of();
    }
    List<BlockPos> out = new ArrayList<>();
    for (MultiblockDefinition.Cell cell : definition.layoutCells()) {
        BlockPos pos = worldPosition.offset(cell.dx(), cell.dy(), cell.dz());
        if (pos.equals(worldPosition) || !level.isLoaded(pos)) {
            continue;
        }
        if (level.getBlockState(pos).getBlock() instanceof ShellBlock) {
            out.add(pos);
        }
    }
    return out;
}
```

> 控制器**不存**「哪些格子是壳」这份账——账在壳的 BE 里。控制器只按骨架范围去问「你是壳吗」。数据单源，重启后不需要任何引导步骤。

## 7. 拆壳 / 控制器被拆 / 自愈

三件事都已经在第 1.2 和 1.3 里做完了，这里只说它们的联动，方便排查：

| 动作 | 路径 |
| --- | --- |
| 玩家拆一格壳 | `ShellBlock.onRemove` 掉原方块 → `BlockEvent.BreakEvent` → `revalidateAround` → 控制器 `validateNow` 判 `INCOMPLETE` → `unformStructure` 还原其余格 |
| 玩家拆控制器 | 控制器 BE 消失 → 每个壳 BE 的 `onLoad`/下一次加载时发现 `controllerPos` 处没有控制器 → 自己还原成原方块 |
| 区块卸载再加载 | 壳 BE 从 NBT 恢复 `originalState`，控制器恢复后重校验，两边自动对齐 |

**不需要**在 `ShellBlock` 里写「找控制器」的半径搜索，也不需要静态 `Map` 缓存——那个做法在区块卸载时会泄漏。

```java
boolean materialSwap = !root.has("materialSwap")
        || JsonSupport.object(root, "materialSwap", "materialSwap")
                .get("enabled").getAsBoolean();
```

末尾传入。**缺省为 `true`**（老配置文件没有这段，行为升级；要退回就把 `enabled` 设 `false`，所有成型逻辑短路）。

## 附录 A · 不会建模，怎么让壳看起来"精美"

三个层次，从便宜到贵，全部是复制改 json，**不需要任何建模工具**。

### A1 换父模型（5 分钟）

`cube_all` 一刀切最平。换成：

| 父模型 | 效果 | 适合 |
| --- | --- | --- |
| `minecraft:block/cube_column` | 上下两种贴图（`end` + `side`） | 竖立的机柱、锅炉身 |
| `minecraft:block/cube_bottom_top` | 上/下/侧三张 | 底座 + 面板 |
| `minecraft:block/cube_column_horizontal` | 横放的柱 | 横向管道 |
| `minecraft:block/orientable` | 正面单独一张（配 `facing` 属性） | 有"面板/屏"的机器 |

例：给黄铜壳加"上下是铆钉板、侧面是格栅"：

```json
{
  "parent": "minecraft:block/cube_column",
  "textures": {
    "end": "irontide:block/shell_brass_end",
    "side": "irontide:block/shell_brass_side"
  }
}
```

多画两张 16×16 就有质变。

### A2 `multipart` 加外缘装饰（半天）

结构外缘会显得"太平"，因为每格都是完整立方体。用原版 `bars` / `wall` 的写法定向外长东西。

`blockstates/shell.json` 从 `variants` 换成 `multipart`：

```json
{
  "multipart": [
    { "apply": { "model": "irontide:block/shell_andesite" } },
    {
      "when": { "north": "false" },
      "apply": { "model": "irontide:block/shell_trim_north" }
    }
  ]
}
```

但这要求方块有 `north/south/east/west` 布尔属性，且要**每 tick 同步邻居状态**——成本上去了。

**更省的做法**：不加属性，做一个独立的装饰方块 `irontide:shell_trim`，成型时在结构外缘单独摆一条。造型归造型，壳归壳，互不干扰。

### A3 借 Create 的现成模型（0 成本）

Create 是 MIT。直接把 `create:block/andesite_casing` 的模型文件复制过来改贴图名，得到的"机械箱体"比任何纯色板都好看。贴图用你自己的，模型留着。

```json
{
  "parent": "create:block/andesite_casing",
  "textures": { "all": "irontide:block/shell_andesite" }
}
```

（父模型引用别的模组的路径，只要它在运行时存在就能用——整合包里 Create 一定在。）

### A4 损伤可视化（进阶，效果最明显）

给 `ShellType` 旁边再加一个 `damaged` 属性（0/1/2/3），`health/healthMax` 掉到阈值时控制器把壳的 `damaged` 调高，blockstate 切到带裂纹的模型。

这是"多方块结构被打会变难看"的最廉价实现，且完全是原版模型能力。tier 越高越值得做。

## 附录 B · 要「真建模」时，AI 生成能怎么用

先说结论：**AI 生成 3D 模型出来的东西是几万面的 glb/obj，没法直接进 Minecraft**。要么体素化成方块阵列，要么只当参考图。

### B1 分清产物

| | 产物 | 谁要 | AI 能不能直接给 |
| --- | --- | --- | --- |
| **模型 json** | 一个格子绘制跨格几何 | 走 BER 的整体大模型 | 要人拼/写坐标 |
| **方块阵列** | 用真方块堆造型（schematic / `{x,y,z,block}` 表） | 成型时 `setBlock` 铺 | **能，靠体素化** |

本教程走的是「方块阵列」之外的第三条路——**换方块**。所以 AI 建模对主流程其实用不上，只在这两种情况下值得上：

1. 想给某个 tier 做**一个整体大雕像/机械塔**（产物二）
2. 想要**甲板/机壳的贴图**（AI 生图，不是生模型）

### B2 贴图路线（推荐，性价比最高）

AI 出 512×512 的「锈蚀钢板 / 黄铜格栅 / 铆钉接缝」纹理图 → 缩到 16×16 或 32×32 → 直接当 `shell_*.png`。

- 缩放用 `脚本/gen_shell_textures.py` 同目录的脚本思路，Pillow 一行 `resize(..., Image.LANCZOS)`
- 关键：MC 的贴图要**低对比、去细节**，否则在游戏里糊成一片。AI 图缩到 16px 后必须手动调对比度

这一步能让壳的观感提升一个档，成本不到一小时。

### B3 模型路线（产物二，链路长）

```
提示词 → AI 3D（Hunyuan3D 2.x / Trellis / Meshy / Tripo / Rodin）
       → model.glb
       → Blender 导入 → Remesh 修改器(Blocks, octree 32~64) → 体素块
       → 导出 obj → Goxel 导入 → 按 MC 调色板染色
       → 自写脚本转 {pos, blockId} 列表
       → 写进 irontide 的结构定义，成型时 level.setBlock 铺
```

| 工具 | 类型 | 备注 |
| --- | --- | --- |
| Hunyuan3D 2.x（腾讯，开源） | 本地 | 免费，12G 显存起 |
| Trellis（微软，开源） | 本地 | 同上 |
| Meshy / Tripo / Rodin | 在线 | 质量最好，几块钱一次 |
| Blender + Remesh(Blocks) | 通用 | 体素化最可控，免费 |
| Goxel | 体素编辑器 | 能直接导 obj 自动体素化 |
| Blockbench | MC 专用 | 1 小时上手，直接出模型 json |

**这条路的问题是**：体素分辨率、调色板映射、朝向对齐三处最容易崩，而且出来的东西是"一坨方块"，细节全靠贴图补。**除非你就是要一个大雕塑，否则别走。**

### B4 最实际的组合

1. 贴图用 AI 生图（B2），一小时内完成
2. 造型用原版父模型 + 少量 `multipart`（附录 A），零建模
3. 真要整体大模型时，用 **Blockbench**（画方块，1 小时能学会）而不是 AI 3D

## 附录 C · 踩坑表

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 结构每秒 `ACTIVE`/`INCOMPLETE` 反复，日志刷屏 | 校验器不认成型态（§4 没做） | 加 `accepted` 分支 + 同步 `brassRatio` 统计 |
| 成型后装甲/血量突然变很低 | `brassRatio` 统计没改，黄铜壳被当空气 | 统计里加 `state.equals(brassFormed)` |
| 崩服 `StackOverflowError` | `setBlock` 标志用了 `3`，邻居更新递归 | 改 `Block.UPDATE_CLIENTS \| Block.UPDATE_KNOWN_SHAPE` + `forming` 守卫 |
| 重启后壳永久卡住，拆了也不还原 | 原始状态没存档 | 原始状态放 `ShellBlockEntity` 的 `saveAdditional` |
| 壳掉落物是壳自己 | 没写 `onRemove` | 照 §1.3，`popResource` 原方块，别写 loot table |
| 编译报 `saveAdditional` 不能重写 | 照着控制器抄了 `SmartBlockEntity` | 壳 BE 继承 `BlockEntity`（那两个方法在 `SmartBlockEntity` 被 `final` 了） |
| 拆壳后其余格不还原 | `BreakEvent` 没触发 `revalidateAround` | 确认 `IronTideEvents` 里那两行还在；或壳破坏后手动 `core.validateNow()` |
| 成型瞬间应力读数乱跳 | 壳被卷进 kinetic 网络 | 壳不实现 `IRotate`、不注册任何 capability |
| 壳被漏斗/管道当成容器 | 壳实现了 `EntityBlock` 就可能被探测 | 不实现任何 `Capability`；必要时加 `neoforge:capability` 排除 |
| 名字显示 `item.irontide.shell` | 语言文件没加 | §2.5 |
| 镐子挖不动 | `mineable/pickaxe` 标签没加 | §2.5 |
| 客户端看不到变化 | 只发了 `UPDATE_CLIENTS` 但服务器端没 `setChanged` | 成型/还原后调 `setChanged()` |
| 老存档进来就崩 | `formed` 解析遇到不存在的方块直接 `throw` | 这是**故意**的：配置错就早崩，别静默降级。真要兼容就 `try/catch` 回 `null` |
