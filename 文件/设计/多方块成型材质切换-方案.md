# 多方块成型材质切换 · 技术方案

> 目标：`core_base_3` 这类多方块结构搭成后，把玩家的 `create:andesite_casing` / `create:brass_casing` 外壳换成自研的精致壳方块，拆掉后原样还原。
> 约束：**不做整体建模**（作者不会建模），**不引入新的渲染管线**，改动面控制在配置 + 一个方块 + 一个 BE 方法内。

---

## 0. 一句话方案

给 `CasingSpec` 加一个可选的 `formed` 字段（成型后要变成的方块状态），结构 `complete` 时逐格 `setBlock` 成 `formed` 并把原状态记在控制器 BE 里；`INCOMPLETE` 时反向还原。校验器额外接受 `formed` 态，避免成型后自判定失败。

---

| 事实 | 位置 | 对方案的影响 |
| --- | --- | --- |
| 结构由 JSON 数据驱动，`legend` 是 `字符 → 方块ID` | `data/irontide/config_defaults/multiblocks/core_base_3.json` | 换材质天然是数据问题，不需要写渲染代码 |

| `SmartBlockEntity` 把 `saveAdditional`/`loadAdditional`、`setRemoved()` 定成 `final` | `AndesiteCoreBlockEntity.java:191,198` | 存档只能走 `write/read(CompoundTag, HolderLookup.Provider, boolean)` |

## 2. 路线选型

### 2.1 候选

| 路线 | 做法 | 改动量 | 出错面 |
| --- | --- | --- | --- |
| **R1 成型态方块（选定）** | `complete` 时把外壳 `setBlock` 成自研 `irontide:shell[type=x]` | 配置 1 字段 + 1 方块 + BE 约 120 行 | 小 |
| R2 整体 BER 模型 | 外壳换不可见占位方块，控制器用 BER 画跨格大模型 | BE 300+ 行 + 模型资源 + 渲染代码 | 大 |
| R3 SuperBlockEntity | 方块抹成空气，实体统一渲染 | 需重写存档/破坏/兼容 | 极大 |

### 2.2 否决理由

**R2 否决**：
1. NeoForge 1.21.1 已移除 `forge:obj` 加载器与 `.mtl`，IE 那套抄不过来，只能手写 `ModelPart` 或手搓 `elements` 坐标——正是「不会建模」的死角。
2. `getRenderBoundingBox` 不扩会闪、扩了要处理视锥与光源；占位方块还要处理 `propagatesSkylightDown`、碰撞箱、BE 卸载自愈。**每一个都是独立故障点**。
3. 收益只是「能做曲面」，而本模组的机械感用 `cube_column` + `multipart` 边框就够。

**R3 否决**：存档兼容、破坏还原、第三方模组交互全部要自己兜，与「不容易出错」直接冲突。

### 2.3 选定 R1 的关键理由

**成型后仍是普通方块**。光照、碰撞、挖掘、掉落、`/setblock`、爆炸、区块卸载全部免费，不需要任何特殊处理。这是唯一能做到「改完不会半夜炸存档」的路线。

## 3. 设计

### 3.1 数据模型

`CasingSpec` 增加一个可空字段：

```java
public record CasingSpec(
        ResourceLocation id,          // 校验期望的方块（玩家要放的）
        @Nullable BlockState formed,  // 成型后变成的方块；null = 不换
        double armor,
        double healthMul,
        double fuelEfficiency
) { }
```

配置（`config/irontide/core.json`）：

```json
"casing": {
  "andesite": {
    "id": "create:andesite_casing",
    "formed": "irontide:shell[type=andesite]",
    "armor": 0.0, "healthMul": 1.0, "fuelEfficiency": 1.0
  },
  "brass": {
    "id": "create:brass_casing",
    "formed": "irontide:shell[type=brass]",
    "armor": 0.05, "healthMul": 1.6, "fuelEfficiency": 1.15
  }
}
```

`formed` 缺省 → 该材质不换，行为与现在完全一致（**向后兼容，老存档不受影响**）。

### 3.2 核心难点：校验环路

成型后世界方块是 `irontide:shell[...]`，但 `Cell.expected()` 期望 `create:andesite_casing`。若不处理，下一 tick 校验立刻判 `INCOMPLETE` → 触发还原 → 又变回期望方块 → 又成型，**无限抖动**。

**解法**（两处同时改，缺一不可）：

1. **校验接受成型态**：`accepted` 判断加一条「世界方块等于该材质的 `formed` 也算匹配」。
2. **统计接受成型态**：`brassRatio` 统计从「== 原方块」扩成「== 原方块 或 == 成型态」。

```java
// StructureValidator.checkLayout 内
BlockState formedForExpected = config.formedFor(cell.expected());

boolean accepted = actual.equals(cell.expected());                    // 原逻辑
if (!accepted && formedForExpected != null && state.equals(formedForExpected)) {
    accepted = true;                                                  // 成型态也算匹配
}
// shellSwap 分支保留原样

// 统计
if (actualBlock == config.andesiteCasing().block()
        || (andesiteFormed != null && state.equals(andesiteFormed))) {
    andesiteCells++;
} else if (actualBlock == config.brassCasing().block()
        || (brassFormed != null && state.equals(brassFormed))) {
    brassCells++;
}
```

> 语义上这等价于「这个位置允许是安山壳，或安山壳的成型外观」，与已有 `shellSwap` 是同一类放宽。

### 3.3 状态机

复用现有 `CoreState`，不新增枚举值：

```
INCOMPLETE --(complete)--> ACTIVE   + formStructure()
ACTIVE     --(缺格)------> INCOMPLETE + unformStructure()
载入存档 --> 控制器重校验一次；壳 BE 自带 originalState，还原逻辑不需要额外引导
```

`DESTROYED` 不参与成型/还原判定（结构坏了也保持当前外观，由维修系统接管）。

### 3.4 防递归

`setBlock` 会触发邻居更新 → `StructureValidator.revalidateAround` → `validateNow` → 又 `setBlock`。

三层防护：

```java
private boolean forming;   // 不存档，纯运行时守卫

// 1) 方法级守卫（必做）
private void formStructure(...) {
    if (forming) return;
    forming = true;
    try { ... } finally { forming = false; }
}

// 2) setBlock 只发客户端更新，跳过邻居形状更新（必做）
level.setBlock(pos, target, Block.UPDATE_CLIENTS | Block.UPDATE_KNOWN_SHAPE);

// 3) 可选加固：revalidateAround 里跳过正在成型的控制器
if (core.isForming()) continue;
```

**实测前提**：`revalidateAround` 只挂在 `BlockEvent.EntityPlaceEvent` 与 `BlockEvent.BreakEvent` 上，两者都是**玩家行为事件**，`setBlock` 本身不会触发。所以主递归路径其实不存在——真正需要担心的是 `node` 里其他地方的 `validateNow()` 直接调用。第 1 条守卫就是为这个准备的，第 3 条是保险。

`UPDATE_CLIENTS | UPDATE_KNOWN_SHAPE`（值 `18`）不触发 `neighborChanged`，是这里能用的最小更新集。

### 3.5 存档：数据放在壳自己身上，不放在控制器

**关键决策——单数据源。** 原始方块状态存在 `ShellBlockEntity` 里，而不是控制器的一个 `Map`。

理由：如果控制器存 `Map<BlockPos, BlockState>`、壳自己又不知道，那么「掉落」「自愈」「重启后还原」三件事全要回来查控制器，任何一处漏掉就是存档损坏。让壳自己记住「我原来是哪一格、原方块是什么」，这三件事全部变成局部问题。

```java
public class ShellBlockEntity extends BlockEntity {
    private BlockPos controllerPos = BlockPos.ZERO;
    private BlockState originalState = Blocks.AIR.defaultBlockState();

    @Override
    protected void saveAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.saveAdditional(tag, registries);
        tag.put("controller", NbtUtils.writeBlockPos(controllerPos));
        tag.put("original", NbtUtils.writeBlockState(originalState));
    }

    @Override
    protected void loadAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.loadAdditional(tag, registries);
        controllerPos = NbtUtils.readBlockPos(tag, "controller").orElse(BlockPos.ZERO);
        originalState = NbtUtils.readBlockState(getLevel().holderLookup(Registries.BLOCK), tag.getCompound("original"));
    }
}
```

> 注意：`ShellBlockEntity extends BlockEntity`（不是 SmartBlockEntity），所以 `saveAdditional/loadAdditional` **没有被 final 掉**，可以正常重写。这一点跟控制器相反，别混。

控制器因此**不需要新增任何存档字段**，`write/read` 一行都不用改。这是本方案比「控制器记 map」省下的最大一块风险。

**自愈**：`ShellBlockEntity.setLevel()` 之后检查 `controllerPos` 处的 BE 是不是对应的控制器且仍在该结构内；不是就 `level.removeBlock(pos, false)`。纯本地判断，不依赖任何全局表。

**掉落**：`ShellBlock.onRemove` 里 `Block.popResource(level, pos, new ItemStack(originalState.getBlock()))`，掉落天然正确，不用写 loot table。

### 3.6 客户端

**零客户端改动**。`ShellBlock` 的 `blockstates/shell.json` + `models/block/shell_*.json` 走原版模型管线，`RenderShape` 保持 `MODEL`。

需要额外同步的只有 `formedCells` 的**数量**（HUD 上如果想显示「已成型 N 格」），走 `setChanged()` 之外的 `sendData` 或在 `CoreScreen` 里按 `state` 推断即可——M1 不做。

### 3.7 掉落与破坏

- `ShellBlock` 的 `getDrops` 返回空（**壳是外观，不是资源**）
- 还原时按 `originalStates` 里存的 `BlockState` 掉落一次，用 `Block.popResource`
- 玩家拆壳 → `onRemove` 通知控制器 `unform()` → 全部还原
- 控制器被拆 → 先 `unform()` 再让控制器正常掉落

> 只允许「控制器驱动壳」，不允许「壳单独存在」。任何 `formed` 方块在脱离控制器后必须自愈成空气（BE 里存 controller pos，找不到就 `level.removeBlock`）。

## 4. 实施计划

| 阶段 | 内容 | 独立验收 | 预估 |
| --- | --- | --- | --- |
| **P0** | `ShellBlock` + `ShellType` + 注册 + 4 套资源 | 创造模式能拿出壳方块、放置显示正常、六面贴图对 | 0.5 天 |
| **P1** | `CasingSpec.formed` + `core.json` 加字段 + 解析 | 加载不报错；`formed` 为空时行为不变 | 0.5 天 |
| **P2** | `StructureValidator` 接受成型态 + 统计改造 | 手动 `setblock` 成壳后核心仍判 `ACTIVE`（不抖） | 0.5 天 |
| **P3** | `formStructure` / `unformStructure` + 防递归 | 搭满结构 → 全体变壳；拆一格 → 全体还原；日志无递归 | 1 天 |
| **P4** | `ShellBlockEntity` 存档 + 自愈 + 掉落 | 成型后重启服务器，结构保持壳态且可拆解还原。拆壳掉原方块 | 0.5 天 |
| **P5** | game test + 手动验收清单 | `runGameTestServer` 全绿 | 0.5 天 |

**每个阶段都必须能单独回退**：P0/P1 全是新增，P2 是加分支，P3 用一个 `FeatureFlag` 包住（config 里 `materialSwap.enabled`，默认 `false`），P4 直接把 flag 关掉即可停用。

## 5. 风险与回退

| 风险 | 触发条件 | 表现 | 回退 |
| --- | --- | --- | --- |
| 校验抖动 | P2 没做或做漏统计 | 每秒 `INCOMPLETE/ACTIVE` 反复，日志刷屏 | 关 `materialSwap.enabled` |
| 递归栈溢出 | 防递归守卫失效 | `StackOverflowError` 崩服 | 同上，并把 `setBlock` 标志改回 `UPDATE_CLIENTS` |
| 存档丢还原信息 | P4 没做 | 重启后壳永久卡住，拆了也不还原 | 手动 `/setblock` 修；规划管理员修复命令 |
| kinetic 网络抖动 | 外壳参与应力网络 | 结构成型瞬间应力读数跳变 | 外壳一律不实现 `IRotate`，不挂 kinetic 成员 |
| 外壳被第三方模组误判 | 存储/管道模组把壳当容器 | 崩或复制物品 | 壳实现 `EntityBlock` 但**不实现任何 capability** |

**总开关**：`config.irontide.materialSwap.enabled = false` 时，本方案全部逻辑短路，等同于现在的行为。

## 6. 验收标准

功能：

1. 空地上放控制器 → 结构不完整 → 外壳保持原方块（**不预先换壳**）
2. 补满最后一格 → 一个 tick 内所有配置过的外壳变 `irontide:shell`，日志一句 `formed N cells`
3. 拆掉任意一格壳 → 全部壳还原成原方块，状态回 `INCOMPLETE`
4. 成型后重启服务器 → 壳保持、拆解仍能还原
5. 成型后 `/setblock` 把某格改成石头 → 触发还原，且不崩
6. `formed` 全部不配 → 行为与改造前逐字节一致（回归）

工程：

7. `runGameTestServer` 全绿
8. 连续成型/拆解 20 次，无内存增长、无日志递归
9. `MaterialSwapGameTest` 至少覆盖：成型 / 还原 / 存档往返 / 缺格不换

## 8. 与现有设计的冲突声明

`AndesiteCoreBlockEntity.validateNow()` 的注释「Never edits blocks」在本方案下**不再成立**，需改为：

> 校验本身不改方块；只有 `complete` 与 `INCOMPLETE` 之间的**状态跃迁**会驱动外壳材质切换，且切换受 `forming` 守卫与 `materialSwap.enabled` 总开关约束。

改动设计文档 `steel-tide-2026-11-03.md` 里的对应条目时按这句话同步。
