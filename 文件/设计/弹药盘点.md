# 弹药盘点（superbwarfare）

> 来源：`mods/superbwarfare-0.8.9.2-hotfix-mc1.21.1-e0c2b27f.jar`（sha256 `f1003f5e6b9d8a6c5e27592aa33df9b88c87b71ff3b5e623f4224222ae140535`）。
> 本文只做盘点，**没有改动任何 ammo 数据/配方**。

## 1. 结论速览

| # | 令牌（gun json 里的写法） | 物品 id | 中文名 | 令牌解析位置 |
|---|---|---|---|---|
| 1 | `@HandgunAmmo` | `superbwarfare:handgun_ammo` | 手枪弹药 | `Ammo.HANDGUN` → `ModItems.HANDGUN_AMMO` |
| 2 | `@RifleAmmo` | `superbwarfare:rifle_ammo` | 步枪弹药 | `Ammo.RIFLE` → `ModItems.RIFLE_AMMO` |
| 3 | `@ShotgunAmmo` | `superbwarfare:shotgun_ammo` | 霰弹枪弹药 | `Ammo.SHOTGUN` → `ModItems.SHOTGUN_AMMO` |
| 4 | `@SniperAmmo` | `superbwarfare:sniper_ammo` | 狙击枪弹药 | `Ammo.SNIPER` → `ModItems.SNIPER_AMMO` |
| 5 | `@HeavyAmmo` | `superbwarfare:heavy_ammo` | 重型弹药 | `Ammo.HEAVY` → `ModItems.HEAVY_AMMO` |

关键结论（直接影响 D-11“合并成 3 类”）：

1. **令牌→物品的映射是 Java 枚举硬编码的**，在 `com/atsuishio/superbwarfare/data/gun/Ammo.class` 里：枚举只有
   `HANDGUN / RIFLE / SHOTGUN / SNIPER / HEAVY`，每个枚举项直接指向 `ModItems.<X>_AMMO`。
   没有配置文件、没有数据包入口 → **无法通过 datapack 把 `@SniperAmmo` 重定向到 `rifle_ammo`**。
2. 所以“狙击并入步枪”只能**逐把枪覆盖 `data/superbwarfare/sbw/guns/<枪>.json`，把 `AmmoType` 里的 `@SniperAmmo` 改成 `@RifleAmmo`**（见第 5 节）。
3. 载具有**另一套弹药**（`small/medium/large_shell_*`、`*_rocket_*`、`*_missile`、`*_bomb`、`mortar_shell`），
   只有车载机枪才是 `@HeavyAmmo` / `@RifleAmmo`。所以“重型留给载具”实际要先决定载具机枪怎么办（见第 6 节风险）。

## 2. 弹药物品与现有配方（jar 内实证）

| 物品 | 单次合成产量 | 主料 | 配方文件 |
|---|---|---|---|
| `superbwarfare:handgun_ammo` | 64 | `c:ingots/copper` | `data/superbwarfare/recipe/handgun_ammo.json` |
| `superbwarfare:rifle_ammo` | 48 | `c:ingots/steel` | `data/superbwarfare/recipe/rifle_ammo.json` |
| `superbwarfare:shotgun_ammo` | 24 | `c:ingots/lead` | `data/superbwarfare/recipe/shotgun_ammo.json` |
| `superbwarfare:sniper_ammo` | 16 | `c:ingots/tungsten` | `data/superbwarfare/recipe/sniper_ammo.json` |
| `superbwarfare:heavy_ammo` | 12 | `c:ingots/steel` | `data/superbwarfare/recipe/heavy_ammo.json` |

五种弹药都是同一个 3×3 排布 `a / bcb / d`：`a`=主料金属、`b`=`c:plates/copper`（铜板）、`c`=`minecraft:gunpowder`、`d`=`superbwarfare:primer`（底火）。

通用前置：

- `superbwarfare:primer`（底火）= 燧石 + 铜板（竖着两格）→ 4 个（`recipe/primer.json`）。
- `superbwarfare:copper_plate`（铜板）= 铜锭 + `superbwarfare:hammer` 无序（`recipe/copper_plate.json`）。

弹药盒（jar 内有模型/贴图的）：`superbwarfare:ammo_box`（通用盒，潜行左击选弹种）、
`handgun_ammo_box`（30）、`rifle_ammo_box`（30）、`shotgun_ammo_box`（12）、`sniper_ammo_box`（12）。
**重型没有独立盒装物品**，只能往通用 `ammo_box` 里存。

> 注意：`data/superbwarfare/recipe/` 下只有 `ammo_box.json`（铁锭×5 + 绿色染料），
> 四个 `*_ammo_box` 物品在 jar 里找不到对应合成配方文件 → 产出途径待实测（可能靠 JEI 外的机制/旧版遗留）。

## 5. 数据结构与“要改哪些 json”

- 玩法数据在 **`data/superbwarfare/sbw/guns/<枪>.json`** 的 `AmmoType` 字段。
- 同名文件 `assets/superbwarfare/sbw/guns/<枪>.json` **只有模型/动画/抛壳点**（对比 `svd`：assets 版 607 字节无 `AmmoType`，data 版 1752 字节有），**不要动**。
- `AmmoType` 有三种写法，覆盖时必须都处理：
  1. 纯字符串：`"AmmoType": "@RifleAmmo"`
  2. 字符串数组：`"AmmoType": [ "a", "b" ]`
  3. 对象数组（带弹种覆盖）：`"AmmoType": [ { "Ammo": "@ShotgunAmmo", "AmmoSlot": "Default", "Override": {...} } ]`
- 覆盖是**整文件替换**（datapack 同名路径优先，没有字段级合并），所以正确做法是：把 jar 里的 `data/superbwarfare/sbw/guns/<枪>.json` 整份拷到 `overrides/kubejs/data/superbwarfare/sbw/guns/<枪>.json`，再改 `AmmoType`。

## 6. 若要把 5 类合并成“手枪弹 / 步枪弹（含狙击）/ 霰弹”

最小改动集（按第 3 节实测清单）：

1. **7 个狙击枪 json**：`awm`、`hunting_rifle`、`k_98`、`mosin_nagant`、`m_98b`、`sentinel`、`svd`
   → `"AmmoType": "@SniperAmmo"` 改成 `"@RifleAmmo"`。
2. **`sniper_ammo` 物品不删**（配方、lang、弹药盒、advancement 都引用它），二选一处理：
   - 方案 A（推荐）：保留 `sniper_ammo`，但改为“穿甲弹”定位，由 KubeJS 改成少量高伤弹配方，只给新加的自制枪用；
   - 方案 B：KubeJS `ServerEvents.recipes` 里 `event.remove({ output: 'superbwarfare:sniper_ammo' })`，同时用 `JEIEvents.hideItems` 隐藏，并隐藏 `sniper_ammo_box`。
3. **`ntw_20` 保持 `@HeavyAmmo`**：它是反器材狙，走重型比走步枪合理；若要它吃步枪弹，需额外加伤害/弹匣 override，否则 3 发弹匣 + 步枪弹会明显变强。
4. **`m_2_hb` 保持 `@HeavyAmmo`**：合并后“重型”只剩它和载具机枪，产量（12/次）依旧稀缺，需要单独看是否调整。
5. **载具**：8 个 `@HeavyAmmo` 载具不用改；若你希望载具机枪改吃步枪弹，那 8 个 `sbw/vehicles/*.json` 也要一起覆盖（同第 5 节规则）。
6. `trachelium` / `secondary_cataclysm` 的数组里没有狙击/重型令牌，**不用改**。

风险与注意：

- `DamageReduce.Type`（Handgun/Rifle/Sniper/...）是**护甲减伤分类**，不是弹药，改弹药时不要顺手改它，否则手感会一起变。
- 覆盖 `sbw/guns` 属于 mod 自定义 reload 数据，jar 内看不到 `reload listener` 的优先级说明；**必须实测**：放进 `overrides/kubejs/data/...` 后重启客户端/服务器，进创造模式给把 AWM，看它是否吃步枪弹。未实测前不要写进教程。
- 合并会同时影响 FTB 任务书 `arms_manual.snbt` 里“五种弹药”那条文案（`5000000000000007`），改数据后要同步改文案。

## 7. 与 D-12（Create 自动化配方）的衔接

现有配方都是**工作台 3×3**。改成 Create 机器时，最小可行组合：

| 目标 | 现有 | 建议 Create 机器 | 备注 |
|---|---|---|---|
| 铜板 | 铜锭 + 锤（无序） | 机械压床（按压） | 保留锤子配方做早期过渡 |
| 底火 | 燧石 + 铜板 | 机械辊压或搅拌 | 一次 4 个，注意产出倍率 |
| 钢锭 | 煤铁粉 + 高炉 | 鼓风机 + 熔炉（批量） | 已有煤铁粉链 |
| 火药 | 原版配方 | 搅拌机（硫/硝/炭） | 需先确认包内是否有硝石来源 |
| 5 类弹药 | 3×3 排布 | 机械辊压/压床 | 建议一次 64，避免手搓 |
