# 退出世界卡在「保存世界中」· 排查记录

更新时间：2026-11-12 · 会话 codex

## 症状

点「保存并退出」/「返回标题画面」后，界面停在**保存世界中**，进度条动画还在转（说明渲染线程活着），但长时间不回到标题画面，只能强制结束进程。

## 已经证明的事实（来自玩家实例日志）

证据：`D:\mc\versions\钢铁潮汐-开发\logs\latest.log`（16:15 那次）与 `logs\2026-11-12-3.log.gz`（13:32 那次），两次都是同一个形状。

1. 世界**已经完整存盘**：
   ```
   [Server thread] Saving players
   [Server thread] Saving worlds
   [Server thread] Saving chunks for level 'ServerLevel[新的世界]'/minecraft:overworld
   [Sable] Saving sub-levels for level .../overworld
   ...
   [Server thread] ThreadedAnvilChunkStorage: All dimensions are saved
   ```
2. 之后 3 个维度的 `LevelEvent.Unload` 也跑了（debug.log 里能看到 Create 的 `Removed Redstone Network Space ...`，`overworld` / `the_end` / `the_nether` 三个都有）。
3. 之后**再没有任何一行 Server thread 的日志**，包括正常退出时必然出现的
   `[Server thread] [ConfigTracker/CONFIG] Unloading configs type SERVER`（这行在 `ServerLifecycleHooks.handleServerStopped` 里，位于 `stopServer()` 返回之后）。
4. 对照**成功退出**（12:56、16:01 两次）：Create 的 3 条 unload 之后 8 毫秒就打印了 `Unloading configs type SERVER`，然后 `Render thread: Stopping!`。

结论：**不是世界存不进去，是集成服务器线程死在 `MinecraftServer.stopServer()` 的最后三行**：

```java
for (ServerLevel level : getAllLevels()) { post(Unload); level.close(); }  // ①
this.isSaving = false;
this.resources.close();                                                     // ②
this.storageSource.close();                                                 // ③
```

客户端此时在 vanilla `Minecraft#disconnect` 里自旋：

```java
while (!integratedServer.isShutdown()) { this.runTick(false); }   // 等 Server thread 死掉
```

Server thread 活着 → 界面永远停在「保存世界中」。所以**根因只能是某个 mod 卡住了 ①②③ 之一**，原版不会为这种情况写任何日志。

## 处置

### 现在（临时）

- 卡住时**可以直接强制结束进程**（任务管理器 → Java(TM) Platform SE binary → 结束任务）。日志已证明世界数据在卡住之前就写完了，直接杀掉不会回滚存档。
- 想要更保险：卡住时先等 30 秒再杀（给可能还在写的 chunk 一点时间）。

### 下次复现时（抓证据）

IronTide 已内置探针 `StuckShutdownWatchdog`（client 包）：

- 检测条件：界面是 `menu.savingLevel`（保存世界中）+ 单人服务器还没 shutdown。
- 超过 **20 秒**没结束就自动抓一次堆栈，最多抓 3 次（每 20 秒一次）。
- 日志长这样（`latest.log` 里就有，ERROR 级别）：

```
[IronTide] 退出世界卡住超过 20 秒（第 1 次抓取），线程清单：Server thread=RUNNABLE | Render thread=RUNNABLE | ...
[IronTide] 卡住线程 Server thread state=RUNNABLE
	at ...
	at ...
```

把这两段发给我即可定位到具体 mod（堆栈里出现谁的方法谁就是）。

### 备用：手动抓（探针没生效时）

卡住的瞬间，在 PowerShell 里跑：

```powershell
$java = (Get-CimInstance Win32_Process -Filter "Name like '%java%'" |
    Where-Object { $_.CommandLine -like '*net.minecraft.client.main.Main*' })
& "C:\Program Files\Microsoft\jdk-21.0.10.7-hotspot\bin\jstack.exe" -l $java.ProcessId > "$env:TEMP\stuck.txt"
```

`stuck.txt` 里找 `"Server thread"` 那一段。

## 候选嫌疑（等堆栈确认，先别乱删 mod）

| 候选 | 依据 |
| --- | --- |
| Sable / Create Aeronautics | 有 `ChunkMap`、`ServerChunkCache`、`IntegratedServer` 的 mixin；`stopServer()` 里的 ① 正是这两个类 |
| Create 6 | 3 条 unload 日志都是它打的，说明它的卸载清理已经跑完，嫌疑较低 |
| KubeJS | mixin 打在 `MinecraftServer` / `ReloadableServerResources`，对应 ② |
| ModernFix | 自带 `chunk_deadlock` 修复（已开启），若确认是它，可试关 `mixin.perf.dedicated_reload_executor` |

## 已知边界

- 这个探针只写日志、不改游戏状态；正常退出世界不产生任何输出。
- 探针只能抓到「卡在保存中」这一种卡死；其它阶段的卡死不在覆盖范围。
